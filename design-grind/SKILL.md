name: design-grind
description: Use when the user says "design grind" or "design-grind"
---

1. Before editing, pin the starting code snapshot (including existing local changes) and capture every meaningful state like loading, empty, error, success, disabled, expanded, dialog, and keyboard states, plus relevant viewport and language variants. Save original captures separately from iteration captures. This starting snapshot is `revision.base` and every board's Before for the entire grind, including rounds after user decisions. Never replace it with an intermediate proposal or accepted iteration. For a state discovered later, capture it from the pinned starting snapshot; disclose unavailable original evidence instead of substituting an iteration.
2. Delegate read-only reviews using the saved reviewer settings in `~/.config/design-grind/reviewers.json`, it stores a `reviewers` list of `{model, effort}`. If missing or unconfigured, ask the user for reviewer model/effort pairs, and save them. When asked to change, update this local file instead of the skill.
3. Supply screenshots, request scores out of 10 for Typography, Hierarchy, Spacing & density, Color & contrast, Iconography, Consistency & polish, Clarity, and Overall, with findings and suggestions. Withhold the passing target and previous scores.
4. Implement useful suggestions, verify changes, recapture affected states, and request fresh reviews until meeting the requested target, defaulting to 9/10 overall each.
5. Invoke `$before-after-review` ([skill instructions](../before-after-review/SKILL.md)) with the cumulative change catalog, original Before captures, current After captures, fixed starting revision, proposed head, brief reasons, and latest exported decisions when available. Keep the board ID and change IDs stable across rounds. Preserve unchanged accepted entries and their evidence; revise only affected proposals. The companion skill builds the board with prior decisions, applies exported selections, and verifies the combination.
